# Instructions for a connected phone assistant

Prepare a reviewed resume and cover-letter package using the user's own facts, designs, Notion page and **private** copy of this generator. Do not reuse another applicant's identity, career history, employer choices or private Notion IDs. Do not claim access that your connected tools do not provide.

1. Identify the exact application page, sources and designs. Retrieve the actual current job posting, factual career sources and user instructions. Preserve originals. Resolve the user's authorization to draft/revise; do not ask again for approval already granted in the session. Observe employer authorship restrictions.
2. Read the current README and NOTION_WORKFLOW.md from the user's generator copy. Draft clean, role-specific Markdown and obtain or respect the applicable wording approval. Keep private standard answers, review annotations and notes outside export sources.
3. Use reference-based profiles and exact Word references for both documents. Keep the letter's paragraph slots compatible. Use the generator to preview and inspect pages. Never independently lay out the PDF.
4. Attach the six inputs using the available Notion upload mechanism, then fetch the saved page for the true file-block IDs. Compute SHA-256 on every exact file. Add one request block under the documented schema with actual dated authorization. Use a new version page or deliberately replace the current request; do not append competing requests.
5. Update only requests/generate.json on the private copy's main branch with the page UUID and a unique requestId. Use the current file SHA when updating; create only if absent. If GitHub file writes are unavailable, give the user the exact page UUID for manual Run workflow. Never commit sources, personal references or generated files.
6. Read the GitHub run status. If it fails, diagnose without exposing token/source content. Inspect uncertain writes before retrying. Do not report success merely because generation was queued.
7. Read back all four returned attachments and the request marker. Download and verify the actual generated Word/PDF files against their sources, including every rendered page. Report visual-review limitations honestly. Put the finished-document links before technical inputs when organizing a package for phone reading.
8. Return one Notion link with the job name and result. This process does not authorize employer upload, messages, terms acceptance or application submission. Do not mark the opportunity Applied without actual submission evidence.

Example request: “Generate my reviewed package for this job, attach resume and letter as Word and PDF in Notion, check the results, and send me the link.”

The code formats reviewed prose; it does not tailor or validate career claims. You need working Notion file uploads and GitHub write permissions to prepare and trigger the entire flow. A chat app's Notion credentials are not the runner's NOTION_TOKEN. Never ask the user to paste that token into chat.
